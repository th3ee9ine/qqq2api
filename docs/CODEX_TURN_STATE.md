# Codex Turn State（账号生命周期）

## 入口与运行模式

系统设置入口为 **系统设置 → GPT → Codex Turn State（自动 / 实验性）**，提供自动管理开关、默认探测模型、模型范围和专属代理选择。账号编辑弹窗和账号列表操作菜单提供手动采集入口。

Turn State 按「账号 ID + 实际上游模型家族」管理。自动开关开启时，模型范围内缺少状态或接近本地保留上限的请求会异步启动维护采集；请求本身不等待采集完成。关闭自动开关会保留已验证状态，停止自动注入和后续自动探测；管理员手动采集不受该开关限制，但仍必须命中配置的模型范围。

无需数据库迁移或重启。保存设置后当前进程的配置缓存立即失效；其他共享数据库的实例最多经过约 60 秒缓存周期读取新配置。旧的全局手动 Token 与手动开关不再读取、写入或注入。

## 采集、生成与续期

1. **候选采集**：候选值只能来自同一账号发出的 Responses JSON / SSE 或成功 WebSocket 握手响应头。SSE 首输出守卫只在暂存头真正提交后观测；失败切换丢弃的暂存响应不会形成候选。
2. **维护请求**：系统向 `POST https://chatgpt.com/backend-api/codex/responses` 发送精确提示词 `Reply with exactly OK.`，使用 `stream: true` 和 `store: false`，首次采集不携带旧的 `X-Codex-Turn-State`。有明确请求模型时使用该实际模型；手动请求未提供模型时使用可编辑默认模型，内置值为 `gpt-5.5`。
3. **续期**：已验证状态以本地发布时间起一小时为保留上限。这是本地生命周期边界，不是上游有效期保证。在上限前十分钟可异步续期；续期期间继续使用尚未到期的已验证值。返回相同 state 不会重置其年龄。
4. **触发范围**：模型范围为空时匹配全部模型；非空时支持精确匹配和仅位于末尾的 `*` 前缀通配。自动路径的客户端模型或映射后实际上游模型任一命中即允许；管理员手动采集校验显式指定或默认选定的单个模型。范围同时约束自动采集、自动续期、自动注入和管理员手动采集；请求模型原文不会被改写。系统不扫描空闲账号，也不做无请求账号的定时保活。
5. **账号状态**：采集不检查账号的 `schedulable`、启用 / 暂停状态、自动过期暂停、过载窗口、限流窗口、临时不可调度标记或账号额度。采集仍必须面向存在的 OpenAI Codex 协议账号，并能从该账号取得可用凭据；凭据失败不会切换到其他账号。
6. **并发语义**：不存在全局 8 worker 上限，也不使用账号服务并发值限制维护 HTTP 连接。不同「账号 + 模型家族」槽可以独立执行；同一槽内的自动与手动触发仍会合并，同时只保留一个运行中的采集或候选验收。这是去重和原子发布边界，不是账号调度限制。
7. **请求预算**：自动路径为缺失或过期状态使用每账号、每模型代次的持久化 burst 预算：一分钟窗口内最多三个采集路由尝试，多实例通过 CAS 共享预算。该预算只限制后台重复上游消耗，不限制其他账号或模型槽并发执行。管理员显式手动采集在模型命中配置范围后，不受自动 burst 预算、进程间 in-flight 租约或 candidate-pending 标记阻挡，但仍遵守上游 429 边界和最终 CAS 发布。
8. **失败处理**：网络、HTTP、凭据、代理或验证失败不会覆盖旧的已验证状态，也不会因 Turn State 探测直接改写账号错误状态或禁用账号。`Retry-After` 仍作为同账号的上游 429 边界，防止通过换路由连续重试限流请求。

额外维护请求**可能消耗上游模型额度**。不检查账号可调度性不等于凭据、额度或上游容量一定可用；管理员对暂停、限流或禁用账号手动采集时应自行承担该请求的上游影响。

## 代理与路由回退

维护请求的路由优先级为：

1. 系统设置中选定的 Turn State 专属代理。
2. 未选定显式代理时，从全部代理记录组成兼容池，优先使用可识别的动态模板。
3. 显式代理不存在、地址非法、路由池为空或无法产生路由时，回退到账号日常绑定代理。
4. 账号未绑定可用代理时使用直连。

显式选定的专属代理与未选定时的兼容池都不检查 `status`、`expires_at`、显示名称或代理供应商。只要协议、host 和端口可构造为合法代理 URL，该记录就可用于采集。如果记录恰好是可识别的 1024Proxy 动态模板，可为它生成新的 sticky SID；其他 HTTP、HTTPS、SOCKS5 或 SOCKS5H 记录按原 URL 使用。供应商、国家、用户名格式和是否真正轮换出口不是采集准入条件。

代理只是维护请求的单次路由覆盖，不修改账号的持久化代理绑定，也不改变普通用户请求的出口。日志不记录代理密码或完整 URL。

采集到候选值后仍会在**当前采集路由**上回放同一 state，但不再强制切回账号日常出口做第二次回放。因此专属代理和账号日常代理是否属于同一出口不是发布前置条件。

## 候选验证与发布边界

收到 `X-Codex-Turn-State` 只会形成候选值，不会立即进入自动注入缓存。自动与手动路径共同要求：

- 在采集路由上携带原值回放成功。
- 采集与同路由回放都观察到真实 `response.created.model` 与 `response.completed.model`；`response.done` 只表示传输结束，不替代 `response.completed`。
- 候选始终归属于发起采集的账号与实际上游模型家族，不能跨账号或跨模型槽发布。
- 状态代次仍与开始采集时一致，且 CAS 发布未输给其他实例或更新的候选。

**自动采集候选**在同路由回放后仍保持暂存，并继续要求后续专用 usage-log 验收请求。只有该请求新落库的 `usage_logs` 在账号、API Key、请求模型、上游响应模型和 state 快照上全部一致，才通过现有 worker 与 CAS 发布；普通业务响应不能用不完整或不匹配的 usage 证据替代这一步。

**管理员手动采集候选**在采集与同路由回放证据完整后，直接标记为手动发布并交给现有 worker 进行 CAS 持久化；不再等待后续专用 usage-log 验收，也不依赖普通可调度流量触发 `/v1/responses`。手动请求接续同槽内已有自动候选时也按这条路径尝试发布；如果该候选无法安全晋升，则重新排队执行手动采集。

两条路径都异步执行。自动触发或手动 API 返回 `queued` 不表示已经获得或发布新 state。在回放、响应模型检查、自动路径 usage 证据或最终持久化失败时，旧的已验证值保持不变。

模型范围先决定某模型是否可以触发采集或使用自动 state，模型归属校验再确保状态不跨槽。状态按实际上游模型家族分槽保存；Astra 家族与 `codex-auto-review` 家族不互通，其他模型使用自身规范化归属。一个模型命中范围，也不代表它可以借用另一模型家族的 state。

状态仍按账号隔离。已知属于其他账号或其他模型家族的回带值会被移除；持久化来源记录和进程内来源缓存用于防止跨账号、跨模型复用。IP 和代理不参与状态归属键。

State 去除首尾空白后只允许可打印 ASCII，最多 4096 字节。它在业务逻辑中是不透明值；292 / 312 / 332 / 356 / 376 等长度、Base64 填充或推测的 envelope 结构都不能单独证明有效、失效、账号归属或模型归属。

## 手动采集 API

管理员可调用：

```http
POST /api/v1/admin/accounts/:id/codex-turn-state/collect
Content-Type: application/json
```

请求体可以为空，也可显式指定单个模型：

```json
{
  "model": "gpt-5.5"
}
```

未传 `model` 或传入空字符串时使用系统默认探测模型。显式模型和默认模型都会先校验为可用的单个模型 ID，然后与配置的模型范围匹配；范围为空时两者都允许。

手动采集只对目标「账号 + 模型家族」的 state **缺失**或按本地一小时保留上限**已实际过期**时启动新采集。只是进入提前十分钟续期窗口、`due=true`、自动开关关闭或账号不可调度，都不会把一个仍有效的 state 视为已过期。

响应不包含完整 state，只返回脱敏诊断。常见结果：

- `202 Accepted` + `status: "queued"`：已启动或接续该账号与模型槽的异步采集、同路由回放和 CAS 持久化。它不会等待普通可调度请求来完成发布；同槽已有工作时仍会合并去重。
- `200 OK` + `status: "already_valid"`：当前槽已有未实际过期的已验证状态，未发起新请求。
- `409 Conflict` + `status: "rejected"`：账号不支持 Codex Turn State、模型 ID 非法、模型不在配置范围内（`reason: "model_out_of_scope"`）、上游 429 冷却边界仍生效，或当前状态机无法安全启动新一代采集。

结果中的 `account_id`、`model`、`status`、`reason`、`message`、`retry_at_ms` 和 `codex_turn_state_auto` 都是诊断信息。`queued` 后应通过账号列表 / 详情重新读取状态，不应将 HTTP 202 视为候选已经完成回放与 CAS 发布。

## 注入优先级与必须携带

注入优先级为：**已确认属于当前账号、当前模型家族的客户端原生续链 state → 当前账号、当前模型家族的已验证自动 state**。自动缓存不覆盖可用的客户端原生值。

自动开关开启时，只有命中模型范围的 Codex 请求才会注入自动 state；同账号、同模型家族下的值还必须已验证且未过期。发送前及 HTTP 重试前都会重新校验范围并选择状态；本地缓存缺失时会同步读取该账号的持久化槽。数据库查找失败会返回固定错误，不会借用其他账号或其他模型的状态。

HTTP 头只在 WebSocket 握手时发送，不能改写已有连接的握手。池化连接按模型家族和实际 state 区分；模型家族切换、state 到期或从无状态变为有状态时不能沿用旧握手。Passthrough 在后续 `response.create` 转发前校验；需要换状态或模型时以 1013 提示客户端重连，在途响应不自动重放。

## 系统设置 API

```json
{
  "openai_codex_turn_state_auto_enabled": true,
  "openai_codex_turn_state_default_model": "gpt-5.5",
  "openai_codex_turn_state_models": "gpt-5.5,gpt-6-astra-*",
  "openai_codex_turn_state_proxy_id": 0
}
```

使用 `PUT /api/v1/admin/settings`。字段省略或 `null` 表示保留原值；关闭自动开关不删除已采集的账号状态。

- `openai_codex_turn_state_auto_enabled`：是否自动触发、注入和续期；不影响管理员手动采集。
- `openai_codex_turn_state_default_model`：没有明确模型的维护任务所用的单个模型 ID，最多 128 字节，允许字母、数字及 `-_.:/`；空值恢复内置值。
- `openai_codex_turn_state_models`：模型范围，逗号或换行分隔、忽略大小写并去重，规范化后最多 1024 字节。空值表示全部模型；支持精确值和仅在末尾的 `*` 前缀通配，其他位置的通配符会拒绝保存。
- `openai_codex_turn_state_proxy_id`：专属代理记录 ID。`0` 表示未显式选定，使用兼容路由池并最终回退账号代理 / 直连；正数表示优先使用该记录，不以状态、过期时间或供应商为准入条件。

模型范围同时约束自动采集、自动注入和管理员手动采集。恢复该配置不会恢复账号 `schedulable`、启用 / 暂停 / 额度门控，不会恢复代理状态、过期时间、名称或供应商筛选，也不会恢复账号服务并发值或全局 8 worker 上限。代理凭据仍只保存在代理管理记录中，设置 API 不回显密码或完整 URL。
运行中缩小模型范围时，已验证状态会保留但不再向范围外模型注入；尚未发布的探测和候选值会取消，后续重新放开范围时可继续使用未过期的已验证状态。

## 账号诊断与日志

账号详情和列表的 `codex_turn_state_auto` 为只读脱敏诊断，包含 `configured`、`set_at_ms`、`probe_at_ms`、`verified_at_ms`、`verified_model`、`probe_not_before_ms`、`expires_at_ms`、`due`、`last_error`、`recovery_pending`、`invalidated_at_ms` 以及按模型分组的 `models`，不包含完整 state。`due` 可以包含提前续期窗口，不等于「已实际过期」，因此手动按钮和后端最终判定不只依赖 `due`。

`last_error` 只返回固定错误码，不包含上游错误正文、代理地址或凭据。Turn State 受管 `account.extra` 字段从普通账号 DTO、导出、导入和复制中移除；普通账号编辑也不会覆盖它们。

管理员使用日志的「上游 Turn State」列默认只显示实际字符长度；长度仅供诊断。`upstream_turn_state` 保存实际出站时的快照，`upstream_response_model` 保存真实上游模型原文。列表与应用 stdout 不新增完整 state 或代理凭据。

## 覆盖路径与边界

自动注入覆盖 Responses HTTP（JSON / SSE）、Responses 透传、`/responses/compact`、经共同 Responses 链路转发的 Chat Completions / Messages 兼容请求、HTTP → WebSocket 桥接，以及 WebSocket 入站、池化 / 专用连接和 passthrough 直连握手。

维护请求仍有有限网络超时、响应体上限、429 边界、凭据错误、可打印 ASCII 校验、模型范围、账号 / 模型归属和候选回放边界；自动路径还保留专用用量证据，手动路径直接进入独立持久化，两者最终都受 CAS 发布约束。这些用于防止资源泄漏、跨账号状态和迟到候选覆盖；除模型范围外，不是账号可调度性、代理供应商或账号并发准入限制。

模拟上游或历史真实账号联调只能证明当次流程与证据链表现，不代表上游一定签发新 state，也不构成模型质量改善或规避 Overload 的保证。
