# Codex Turn State（账号自动生命周期）

## 入口与操作

入口：**系统设置 → GPT → Codex Turn State（自动 / 实验性）**。提供自动管理开关、默认探测模型和模型范围，默认关闭，不需要填写 Token。

开启后按「账号 ID + 实际上游模型」管理状态；匹配模型的请求发现 Token 缺失或临近本地参考期限时，异步发起额外 Responses 探测。响应头中的值只是候选；必须继续通过同出口回放、日常出口回放、`response.created` / `response.completed` 模型检查与 `usage_logs` 证据闭环才可原子发布。关闭后保留已验证值，停止自动采集、注入和后续探测；已经发出的探测可能执行到超时，其返回值会丢弃。

无需数据库迁移或重启。保存后当前进程配置缓存失效；其他共享数据库实例最多经过约 60 秒缓存周期读取新配置。升级前保存的手动全局 Token 和手动开关不再读取、写入或注入；不会把旧手动开关转换成自动开关。

## 自动采集、生成与续期

1. **采集**：候选值只能来自同一账号发出的 Responses JSON / SSE 或成功 WebSocket 握手响应头。SSE 首输出守卫只在暂存头真正提交后观测；失败切换丢弃的暂存响应不会被当作可用值。响应头长度仅作诊断记录，292 / 312 / 332 / 356 / 376 都不是有效或失效信号。
2. **生成**：发出 `POST https://chatgpt.com/backend-api/codex/responses`，精确提示词为 `Reply with exactly OK.`，使用 `stream: true`、`store: false`，不携带旧的 `X-Codex-Turn-State`。使用目标状态所属的实际上游模型；没有明确请求模型时才使用可编辑的默认探测模型（初始 `gpt-6-astra`）。已排队的探测和 IP 轮换固定使用其所属模型，修改默认模型不会把这些请求切换到另一个模型。没有该头、非 2xx、网络失败或真实响应模型不匹配均算失败；不伪造或改写不透明 state。
3. **续期**：以本地验证发布时间起一小时作为自动 state 的保留上限；这只是客户端侧上限，不是上游对有效期的保证。匹配请求在上限前十分钟触发异步续期，续期期间继续使用已验证且未到本地上限的值；超过上限的自动值不再注入。上游不保证每次都签发不同的新 state；返回同一值不会重置它的年龄。
4. **触发方式**：由符合模型范围的网关请求触发，不扫描空闲账号、不做无人使用账号的定时保活。首个请求不会等待探测；本次无 Token 时正常转发，探测成功供后续请求使用。
5. **请求凭据和出口**：维护探测固定使用重新读取的同一账号凭据；出口按“显式动态 Turn State 代理优先、无动态配置时普通 IP 池回退”的规则选择，不修改账号日常代理绑定。OAuth 使用现有 access-token provider；Setup Token 使用其 bearer 凭据；Agent Identity 使用现有 assertion / task 注册流程。探测前重新读取账号，跳过已禁用、暂停或限流等不可调度账号。
6. **并发和成本控制**：单进程每账号与模型串行合并，同时最多八个后台任务。当该账号、该模型没有有效 state 时，只开启一个 **1 分钟窗口内最多 3 次**、使用不同新出口的有界采集 burst；成功候选、429、不可重试错误、关闭开关或窗口到期都会提前停止，因此“3 次”是上限，不会为了凑满次数继续请求。窗口和状态代次用尽后不按分钟自动重置，避免持续流量触发无限换 IP；已有仍有效 state 的提前续期仍沿用五分钟节流。每次网络尝试最多十二秒，单次持久化最多三秒；只读取最多 128 KiB 探测响应体。该大小限制仅用于维护探测，不限制用户的 SSE 流。
7. **失败处理**：保留已有 Token，记录固定错误码和最后探测时间。Turn State 探测的 HTTP / 网络失败不写账号错误状态、不禁用账号。OAuth access-token 刷新、Agent Identity task 注册仍遵循项目原有凭据生命周期策略。
8. **隔离和保存**：状态按账号 ID 与规范化模型家族分别存储在 `account.extra` 的受管模型键下，各模型槽用独立顶层 JSONB 键做 CAS 原子发布，后台线程不修改请求或调度器共享的账号对象。采集值在回放与 usage 证据闭环前只作为候选，不能进入自动注入缓存；验证失败或持久化失败保留旧的已发布值。同时到达的新一代已验证结果可以阻止更早探测的迟到结果覆盖。普通账号编辑保留受管状态，导出 / 导入 / 复制不迁移该状态。更新时间和固定错误码可查看账号 API 的安全诊断字段。

额外探测**可能消耗上游模型额度**，无需普通用户请求等待不代表免费。缺失 state 的 burst 在每个新出口发请求前先用账号、模型家族和状态代次做持久化 CAS 占位；多实例竞争总计也不得超过三次，占位失败时不发送上游请求。后台任务满载时按账号和模型家族合并排队，空出任务槽后自动继续；数据库写入失败时保留旧的已发布状态，但不会把持久化重试变成新的上游探测。429 的账号级边界写入失败时只做有限的数据库重试，失败后保留 dirty 状态，不重新发送上游请求。

## IP / 代理池轮换

Turn State 维护探测先看代理管理中显式标记为 `codex-turn-state-probe:<name>` 的动态 1024Proxy 记录。为兼容已存在的本地记录，host/port 正确且名称包含独立 `state` 标记的 `team3-state-...` 形式也会被识别；静态或其他协议不会因为名称相似而进入动态分支。动态记录必须使用同一 host、端口、供应商账号、密码和两字母固定国家；可以用裸模板自动生成新的 sticky SID，也可以提供已生成的 sticky SID。只要存在有效的动态配置，就不会混用普通 IP 池；显式动态记录损坏或凭据/国家混杂时 fail closed。

没有有效动态配置时，才读取代理管理中的 `active`、未过期普通代理作为 IP 池，过滤空 host、非法协议、重复出口和账号当前线路，随机选取最多三个不同出口。每个出口在一次维护运行中只使用一次无 state 采集加必要的同出口回放，不重复轮换；缺失 state 时只创建一个最长 60 秒、最多三次采集的 burst。同一状态代次用尽后不会每分钟重新创建 burst。普通池为空时不会偷偷切换账号，也不会用当前线路伪造“新出口”采集，维护探测失败并保留旧有效值。

缺失 state 或网络故障可在当前有界 burst 内继续尝试尚未使用的出口；400、401、402、403、404、422、429 等请求、权限或额度拒绝立即停止，不能通过换出口绕过这些拒绝。所有尝试均使用同一账号凭据与同一实际模型，不携带旧 Turn State。新真实响应、候选待验证或开关关闭都会使进行中的旧探测退出。429 按 `Retry-After` 或本地有限退避停止，不通过换 IP 连续重试限流请求。429 冷却是账号级边界，在 Astra 与 `codex-auto-review` 等模型槽之间共享；边界单调持久化到账号顶层受管字段，不会因切换模型、进程重启或模型槽 CAS 竞争而缩短。

代理池仅供额外探测使用，不改账号代理绑定和用户请求的出口。跨出口取得的状态能否在账号原线路被接受取决于上游，不能仅凭观察到响应头或某个长度推断 IP 绑定规则。探测仍会消耗账号额度；日志诊断不记录代理密码或完整 URL。显式标记的专用动态记录不会进入普通账号的自动代理分配；管理员仍不应手动把它绑定给日常账号流量。四阶段人工验收按账号与专用 API Key 记录一小时本地预算：每个 sticky SID 只允许一次采集，最多三个不同 SID，429 会冻结整个预算而不是换出口继续。基线、国家、已用 SID 的 SHA-256 摘要和冷却边界以账号级 CAS 持久化；重启或多实例不能重新获得已用 SID，持久化失败则不发送验证请求。该一小时窗口只是本地保留上限，不代表上游保证有效或自动续期。

## 长度与候选状态边界

292 / 312 / 332 / 356 / 376 只表示曾观察到的 state 字符长度，用于日志对比和排障。长度、Base64 填充、密文块数或任何推测的 envelope 结构都不能单独证明 state 有效、失效、属于某类账号、属于某个模型，或代表模型质量变化；也不能据此撤销旧值、触发恢复、跳过冷却或发布候选值。

收到响应头只会形成同账号、同模型家族的候选值。候选值必须依次通过同出口回放、账号日常出口回放，并由真实 `response.created.model`、`response.completed.model` 与 `usage_logs` 的账号、API Key、请求模型和上游响应模型证据闭环确认。模型降级、事件缺失、`response.failed`、回放拒绝或证据不一致都会使候选失败；HTTP 200、回复文本为 `OK` 或任意 state 长度都不能替代这些检查。

采集失败和验证失败都不能覆盖旧的已验证值。HTTP 请求、WS 握手和后台探测携带状态代次；迟到结果只有在代次仍一致且完整验证通过时才可 CAS 发布。一般状态快照同步不是跨实例实时屏障，但 Turn State 维护请求在每个新出口、同出口回放和日常线路回放前会窄读账号级持久化 429 边界，发现未来边界或窄读失败就停止并 fail closed。

## 注入优先级与模型范围

优先级：**官方客户端原生携带且已确认属于当前账号、当前模型家族的续链 state → 当前账号、当前模型家族的已验证自动 state**。原生 state 正常透传，自动缓存不得覆盖它；来源不明、其他账号或其他模型家族的回带值也不能覆盖当前可用值。长度变化不改变该优先级。

候选值验收必须同时看到真实 `response.created.model` 与 `response.completed.model`，以及新落库的 `usage_logs.upstream_response_model`；`response.done` 可以继续作为普通传输终止事件，但不代替 Turn State 验收的 `response.completed` 证据。Astra 家族包括 `gpt-6`、`gpt-6-astra`、`gpt-6-astra-*` 及其供应商前缀变体；`codex-auto-review`、`codex-auto-review-*` 及其供应商前缀变体属于独立的 auto-review 家族。created、completed 和 usage 上游模型都必须属于请求所预期的同一家族，Astra 与 auto-review 不互通。请求字段、响应事件和 usage log 中的真实模型原文均不改写；家族归一化只用于归属与校验。

自动管理适用于 OpenAI OAuth / Setup Token 的 Codex 协议；API Key 和其他平台不注入自动值。采集值仅用于同一账号、同一模型家族；同账号同模型家族可以跨 IP / 代理使用。IP 不参与缓存键、持久化键和状态代次。不同模型家族分别获取、回放、发布和续期；一个家族的候选或失败不能影响另一个家族的已验证状态。

模型范围：为空匹配全部；逗号或换行分隔，忽略大小写、去重，支持精确值和末尾 `*` 前缀匹配，规范化后最多 1024 字节。客户端模型或映射后上游模型任一命中即可；两者均未知时也允许。真实响应可被采集，但自动注入和主动探测只由匹配范围的请求触发。默认探测模型仅用于没有明确模型的任务，初始为 `gpt-6-astra`，清空保存恢复默认。正常请求使用映射后的实际上游模型家族作为状态归属；客户端别名仅用于匹配配置范围。此设置不改变用户请求模型。

State 去除首尾空白后仅允许可打印 ASCII，最多 4096 字节。应用把 state 当作不透明值，不根据长度、填充、密文块数或推测的 envelope 结构决定是否发布。一小时仅是已验证自动 state 的本地保留上限，不是官方有效性证明，也不能替代真实回放与模型证据。

## 必须携带与升级行为

符合自动开关和模型范围的正常上游请求，只要同账号同模型家族有可用状态就必须携带；不会借用其他账号或其他模型家族的状态。发送前（包括 HTTP 重试）再次选择，缺少可用值时同步读取该账号的持久化状态，避免仅因本地缓存为空而漏带。正向缓存最多五秒刷新一次；空结果不做负缓存，并发查找合并。数据库查找失败会返回固定错误，不以「系统无可用状态」为由空头发送。后台获取 / 续期探测是专门的签发请求，仍不携带旧值；只有完整验证并原子发布的新值才可进入后续自动注入。

3.0.9 及之前存储的单账号 Token 没有可靠的模型归属，升级后不自动归入默认模型，也不再注入；通过实际请求或同模型家族探测重新采集并验证。旧诊断元数据保留在数据库，普通账号编辑不会删除受管状态，DTO 和导出不暴露模型 Token。本地保留上限为一小时，相同 state 再次出现不会重新起算；上游拒绝、真实模型不匹配或证据不完整时不会发布候选值。

## 覆盖路径

- Responses HTTP（JSON / SSE）、Responses 透传和 `/responses/compact`。
- 经共同 Responses 链路转发的 Chat Completions、Messages 兼容请求，以及 HTTP → WebSocket 桥接。
- WebSocket 入站、池化 / 专用连接、passthrough 直连握手。获取和拨号时重新解析配置，自动值变化时按 Token 摘要区分新握手；关闭自动管理时恢复原生状态。
- 账号 Responses 测试与调试工作台不会读取手动 Token。默认模板生成只读，不会启动自动付费探测。

HTTP 头仅在 WebSocket 握手发送，不能改写已有连接的握手。池化连接按模型家族和实际状态区分，模型家族切换、已验证 state 到期或从无状态变为有状态时不能沿用旧握手；固定续链也不能绕过。Passthrough 在后续 response.create 转发前校验；需要换状态或模型时以 1013 提示客户端重新连接，该帧不会发往上游。仍有效且归属正确的握手状态可继续使用。在途响应不自动重放。此功能不替换正常请求的模型、reasoning 或 HTTP 状态码，不添加无限 Overload 重试。

## 系统设置 API

仅启用自动能力：

```json
{
  "openai_codex_turn_state_auto_enabled": true,
  "openai_codex_turn_state_default_model": "gpt-6-astra",
  "openai_codex_turn_state_models": "gpt-6,gpt-6-astra,gpt-6-astra-*,codex-auto-review,codex-auto-review-*"
}
```

使用 `PUT /api/v1/admin/settings`。字段省略或 `null` 表示保留；关闭自动开关不会删除已采集的账号 Token。

GET / PUT 提供 `openai_codex_turn_state_auto_enabled`、`openai_codex_turn_state_default_model` 和 `openai_codex_turn_state_models`。默认模型是一个最多 128 字节的完整名称，支持字母、数字及 `-_.:/`，不支持空格、列表和通配符；空值恢复内置默认，省略或 `null` 保留原值。旧的 `openai_codex_turn_state`、`openai_codex_turn_state_enabled`、全局配置诊断和手动设置时间已从接口移除；旧客户端发送这些未知字段时会被忽略，不影响自动配置。

账号详情和列表的 `codex_turn_state_auto` 为只读诊断：`configured/set_at_ms/probe_at_ms/expires_at_ms/due/last_error/recovery_pending/invalidated_at_ms` 及按模型分组的 `models`，不包含 Token。`due` 表示按本地保留上限需要续期，不代表开关已开启或探测正在运行。`last_error` 仅允许固定码，例如 `response_model_mismatch`、`response_model_missing`、`http_429`、`missing_state`、`transport_failed`；不包含上游错误正文、代理地址或凭据。受管 Extra 字段从普通 DTO 和账号导出中移除；设置审计只记录变更字段名。

## 管理员使用日志

使用日志的「上游 Turn State」列默认只显示实际字符长度（例如 292、312、332、356、376），长度仅供诊断；点击数字打开详情弹窗，查看和复制完整值。列表及悬停提示不显示 Token 内容；管理员 CSV 导出仍包含完整值。字段 `upstream_turn_state` 保存实际出站时的快照，HTTP 使用产生日志的那次请求，重试不会用后来刷新的账号缓存覆盖旧请求；不读取上游响应里的新 Token。WebSocket 使用该连接握手时发送的状态，后续复用连接的轮次沿用同一快照，头部不会逐轮重发。`upstream_response_model` 保存真实上游模型原文，包括日期、构建号或供应商前缀变体，不改写为家族规范名。

空字符串表示已观测到未携带，NULL / 字段缺失表示历史或未观测数据。字段仅由管理员日志 DTO 返回，普通用户日志、账号导出和应用 stdout 不新增完整值。迁移 239 只增加可空 TEXT 列，不回填历史请求的未知状态。

## 验证边界

当前产品仅提供账号自动生命周期。State 内容按不透明值处理；字符长度不能证明签名有效、上游必然接受、模型质量提升或避免 Overload。

测试使用模拟上游检查采集提交时机、账号隔离、并发去重、异步生成、提前续期、失败冷却、禁用行为、HTTP/Compact/WS 请求头策略、设置保留与脱敏以及前端保存。模拟测试通过不等于真实上游一定返回新的 Turn State，也不构成质量收益证明。

真实账号联调入口为 `TestCodexTurnStateLiveIntegration`，默认跳过。显式设置 `CODEX_TURN_STATE_LIVE_ACCOUNT_FILE` 为仅含一个 OpenAI OAuth 账号的导出 JSON 绝对路径后才会联网；`CODEX_TURN_STATE_LIVE_MODEL` 可覆盖默认模型。缺失有效 state 时只允许一次最长 60 秒、最多三个新出口的有界采集 burst，使用真实服务请求构造、后台探测和回放验证逻辑，内存仓库与标准 `net/http` 网络适配器。测试不导入生产数据库、不修改原账号文件、不刷新登录凭据；需提供仍有效的 access token。适配器遵循 `HTTPS_PROXY`，不会自动读取 macOS 系统代理。不要把该测试当作生产连接池、数据库、OAuth 刷新或 WS 的端到端验证。

联调先记录无旧 state 的基线，再检查新出口采集、同账号同模型家族回放、日常出口回放和自动注入。成功必须以真实 `response.created`、`response.completed`、state 发送快照及 usage log 闭环为准；任何长度都只记录，不向本地逻辑注入模拟失效信号，也不能把 SSE 的 `response.failed` 计为推理完成。
