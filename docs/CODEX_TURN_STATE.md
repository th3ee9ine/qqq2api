# Codex Turn State（账号生命周期）

## 入口与运行模式

管理后台侧栏的 **Codex Turn State** 是独立入口，集中提供自动管理开关、默认探测模型、模型范围、采集 IP 池、账号脱敏状态和手动采集。账号编辑弹窗和账号列表操作菜单仍保留手动采集快捷入口。系统设置页不再重复展示 Turn State 配置。

Turn State 按「账号 ID + 实际上游模型家族」管理。自动开关开启时，模型范围内缺少状态或进入配置续采窗口的活跃业务请求会异步启动维护采集；请求本身不等待采集完成。后台每分钟扫描已有模型槽，为已实际过期的槽自动续期，并在失败退避与 `Retry-After` 到期后重新采集失败槽；从未采集的空槽不会因后台扫描而首次全量采集。关闭自动开关会保留已验证状态，停止自动注入和后续自动探测；管理员手动采集不受该开关限制，但仍必须命中配置的模型范围。

无需数据库迁移或重启。保存设置后当前进程的配置缓存立即失效；其他共享数据库的实例最多经过约 60 秒缓存周期读取新配置。旧的全局手动 Token 与手动开关不再读取、写入或注入。

### 管理页一键采集与进度

「一键采集」以点击时管理页已加载的全部符合条件账号为目标，不受当前搜索词或采集状态筛选影响。页面调度器最多同时运行 3 个账号轮次；每个 worker 会等待当前账号的全部目标模型进入成功、失败或跳过终态，再取下一个账号，而不是在提交 API 返回后立即扩大并发。如果已提交轮次因账号移除或资格变化而跳过，页面会中止尚未完成的 HTTP 请求并退役对应 worker，不会立即复用该并发槽；因此同批剩余但尚未提交的账号可能会被标记为跳过。

账号级、模型级和总体进度使用手动采集响应中的 `model_targets` 将具体模型映射到真实 owner 槽，并通过后续账号详情轮询更新；一个具体模型只在其 owner 进入终态后计入完成。“已提交”只统计已实际发出采集请求的账号；未提交就因资格变化跳过的账号不计入。批次结束时会固定当次汇总快照，后续单账号重采不会改写已完成批次的百分比与结果数。每个模型行独立展示自身的 `expires_at_ms`，包括有效至、已过期或待续期时的当前到期时间；不使用其他模型或账号汇总状态代替。

该批次仅存在于当前管理页内存，不是服务端持久化的后台 job，也没有可恢复的批次 ID。关闭或离开页面后，尚未提交的账号不会继续由该页面调度；已经提交到服务端的单账号采集仍遵循原有异步采集语义。

### 采集任务中心

服务端会为手动、一键、业务请求自动采集、后台续期和管理员重试创建账号 / owner 模型级任务记录。独立管理页展示最近任务，对 `queued` 和 `running` 任务轮询进度；详情页展示账号、请求模型、真实 owner、来源、状态、阶段、百分比、计数、创建 / 启动 / 更新 / 结束时间、耗时、固定安全错误码和脱敏事件时间线。

任务 API 位于 `GET /api/v1/admin/accounts/codex-turn-state/tasks`、`GET /api/v1/admin/accounts/codex-turn-state/tasks/:task_id`、`POST /api/v1/admin/accounts/codex-turn-state/tasks/:task_id/cancel` 和 `POST /api/v1/admin/accounts/codex-turn-state/tasks/:task_id/retry`。列表响应只返回任务摘要，事件历史仅由详情 API 返回。排队或运行中的任务可取消；失败或已取消任务可以按原账号与模型快照创建来源为 `retry` 的新任务，原任务保留不变。

任务注册表是当前进程内的有界诊断历史，不写入数据库，进程重启后不可恢复，也不代替持久化的 Turn State 模型槽状态。任务快照不包含账号凭据、代理 URL、完整 Turn State 或上游错误原文。

## 采集、生成与续期

1. **候选采集**：候选值只能来自同一账号发出的 Responses JSON / SSE 或成功 WebSocket 握手响应头。SSE 首输出守卫只在暂存头真正提交后观测；失败切换丢弃的暂存响应不会形成候选。
2. **维护请求**：系统向 `POST https://chatgpt.com/backend-api/codex/responses` 发送精确提示词 `Reply with exactly OK.`，使用 `stream: true` 和 `store: false`，首次采集不携带旧的 `X-Codex-Turn-State`。自动采集使用触发请求的实际模型；手动采集由服务端展开配置范围内的全部具体模型。
3. **续期**：已验证状态以本地发布时间起一小时为保留上限。这是本地生命周期边界，不是上游有效期保证。自动采集周期可配置为 1 到 60 分钟，默认 50 分钟；活跃业务请求在「最近一次成功采集或复验时间 + 配置周期」到达后可异步提前续采。已有模型槽到达一小时实际本地过期时间后，即使没有新业务请求，也会由每分钟扫描一次的后台任务自动续期。续期期间继续使用尚未到期的已验证值；返回相同 state 只会重置下一次续采计时，不会改变原始发布时间或延长一小时硬过期。
4. **触发范围**：模型范围为空时匹配全部模型；非空时支持精确匹配和仅位于末尾的 `*` 前缀通配。自动路径的客户端模型或映射后实际上游模型任一命中即允许。手动路径直接采用精确配置项；范围为空或包含通配符时，从所选账号的真实模型目录展开后再匹配，目录读取或解析失败会整体失败关闭，不会退化为只采默认模型。范围同时约束自动采集、自动续期、自动注入和管理员手动采集；请求模型原文不会被改写。后台扫描只检查已经存在持久化记录的模型槽，不会为从未采集的空槽或无任何槽记录的账号发起后台首次全量采集。
5. **账号状态**：只有账号管理中当前正常可调度的 OpenAI Codex OAuth / Setup Token 账号可以采集。停用、错误、手动暂停、自动过期暂停、过载、限流、临时不可调度或额度耗尽的账号不出现在采集列表，不参与自动采集，手动 API 也会拒绝。采集期间会重新读取账号状态；若账号变为不可调度，立即停止本轮。凭据失败不会切换到其他账号。
6. **并发语义**：不存在全局 8 worker 上限，也不使用账号服务并发值限制维护 HTTP 连接。自动路径的不同「账号 + 模型家族」槽可以独立执行；一次同账号手动采集展开的多个 owner 则按账号串行访问上游，不会按模型数并发放大请求。同一槽仍只保留一个运行中的采集或候选验收；任一目标 owner 忙碌时，新的手动批次整体拒绝，不会只排队其他 owner。
7. **请求预算**：一次采集是一轮完整路由池轮询，不是单个 IP 尝试。每轮对快照内的去重路由最多各访问一次，采集并回放成功后立即停止；全部失败才结束本轮。自动路径为缺失、过期或失败重采使用每账号、每模型代次的持久化 burst 预算：一轮完整 IP 池轮询只消耗一次 attempt，多实例通过 CAS 共享预算。管理员显式手动采集不受自动 burst 预算、进程间 in-flight 租约或 candidate-pending 标记阻挡。
8. **失败处理**：网络、HTTP、凭据、代理或验证失败不会覆盖旧的已验证状态，也不会因 Turn State 探测直接改写账号错误状态或禁用账号。本轮单路由失败（包括 429）不会跳过后续 IP；`Retry-After` 仍持久化为下一次自动采集的同账号边界。已有模型槽的自动采集失败后，后台扫描会在五分钟失败退避和持久化 `Retry-After` 都已到期后重新采集，包括仍保留未过期旧 state 的失败槽。管理员单账号手动采集和管理页一键采集都忽略采集前已存在的自动重试计时与持久化冷却，可在失败轮次结束后立即重新提交；已在进行的同槽工作仍会被拒绝。

额外维护请求**可能消耗上游模型额度**。手动绕过的只是 Turn State 采集冷却，不是账号调度准入、模型范围、响应验证或 CAS 发布边界。

## 代理与路由回退

维护请求的路由优先级为：

1. 独立页面配置的 Turn State 专用 IP 池；最多保存 256 个稳定去重的 `socks5://username:password@host:port` URL。只要专用池非空，本轮只使用专用池，不会扩大到全局 IP 管理池。
   管理页支持按“一行一个 URL”批量追加到现有专用池；空行会被忽略，每行首尾空白会被清理，随后复用原有 URL 校验和规范化规则，并继续执行稳定去重与整池 256 项上限。单次批量输入限制为 1024 个物理行和 1 MiB，超限或任一非空行无效时整批不应用。该功能不改变保存、回退或采集路由语义。
2. 专用池未配置或显式保存为空数组时，使用全局「IP 管理」池中的可构造路由。
3. 专用池为空，且全局 IP 管理查询成功并明确返回零条记录时使用直连。全局池查询失败、配置异常或非空但全部记录不可构造时，本轮以 `probe_pool_unavailable` 失败，不会误降级到直连。采集永远不回退到账号日常绑定代理。

全局 IP 管理回退池不检查 `status`、`expires_at`、显示名称或代理供应商。只要协议、host 和端口可构造为合法代理 URL，该记录就可用于采集。如果专用 URL 或全局记录恰好是可识别的 1024Proxy 动态模板，会转换为固定 sticky SID，保证候选采集与同路由回放使用同一出口；不能识别为模板的合法 SOCKS5 URL 仍按普通静态路由使用。

代理只是维护请求的单次路由覆盖，不修改账号的持久化代理绑定，也不改变普通用户请求的出口。日志不记录代理密码或完整 URL。

采集到候选值后仍会在**当前采集路由**上回放同一 state，但不再强制切回账号日常出口做第二次回放。因此专属代理和账号日常代理是否属于同一出口不是发布前置条件。

## 候选验证与发布边界

收到 `X-Codex-Turn-State` 只会形成候选值，不会立即进入自动注入缓存。自动与手动路径共同要求：

- 在采集路由上携带原值回放成功。
- 采集与同路由回放都观察到真实 `response.created.model` 与 `response.completed.model`；`response.done` 只表示传输结束，不替代 `response.completed`。
- 候选始终归属于发起采集的账号与实际上游模型家族，不能跨账号或跨模型槽发布。
- 状态代次仍与开始采集时一致，且 CAS 发布未输给其他实例或更新的候选。

**业务请求触发的自动采集候选**在同路由回放后仍保持暂存，并继续要求后续专用 usage-log 验收请求。只有该请求新落库的 `usage_logs` 在账号、API Key、请求模型、上游响应模型和 state 快照上全部一致，才通过现有 worker 与 CAS 发布；普通业务响应不能用不完整或不匹配的 usage 证据替代这一步。候选最多等待 10 分钟；期间任务保持 `verifying` 且可由管理员取消，超时仍无合格证据时以安全码 `usage_log_missing` 持久化失败并开放重新采集。

**后台过期续期与失败重采候选**在采集和同路由回放证据完整后直接交给现有 worker 进行 CAS 持久化，不等待后续业务流量或 usage-log 验收；它仍受自动开关、模型范围、账号可调度性、失败退避、`Retry-After`、burst 预算和 CAS 边界约束。

**管理员手动采集候选**在采集与同路由回放证据完整后，直接标记为手动发布并交给现有 worker 进行 CAS 持久化；不再等待后续专用 usage-log 验收，也不依赖普通可调度流量触发 `/v1/responses`。手动请求接续同槽内已有自动候选时也按这条路径尝试发布；如果该候选无法安全晋升，则重新排队执行手动采集。

上述三类路径都异步执行。自动触发或手动 API 返回 `queued` 不表示已经获得或发布新 state。在回放、响应模型检查、业务请求自动路径的 usage 证据或最终持久化失败时，旧的已验证值保持不变。

模型范围先决定某模型是否可以触发采集或使用自动 state，模型归属校验再确保状态不跨槽。状态按实际上游模型家族分槽保存；Astra 家族与 `codex-auto-review` 家族不互通，其他模型使用自身规范化归属。一个模型命中范围，也不代表它可以借用另一模型家族的 state。

状态仍按账号隔离。已知属于其他账号或其他模型家族的回带值会被移除；持久化来源记录和进程内来源缓存用于防止跨账号、跨模型复用。IP 和代理不参与状态归属键。

State 去除首尾空白后只允许可打印 ASCII，最多 4096 字节。它在业务逻辑中是不透明值；292 / 312 / 332 / 356 / 376 等长度、Base64 填充或推测的 envelope 结构都不能单独证明有效、失效、账号归属或模型归属。

## 手动采集 API

管理员可调用：

```http
POST /api/v1/admin/accounts/:id/codex-turn-state/collect
Content-Type: application/json
```

请求体可以为空；也可以传入 `source: "manual"` 或 `source: "bulk"` 标记单账号手动采集与管理页一键采集，省略时默认为 `manual`，其他值会被拒绝。为兼容旧客户端，服务端仍接受历史 `model` 字段，但不再用它缩小普通采集范围；配置的服务端模型范围是本轮唯一权威来源。任务中心发起的 `retry` 由服务端内部绑定原任务的账号、具体模型与 owner，不接受客户端用 `source` 伪造。

精确配置项即使未出现在目录中也会直接尝试。范围为空或含尾部 `*` 时，服务端先读取当前账号的真实模型目录并展开所有匹配的具体 ID；目录不可用时返回 `model_catalog_unavailable`，不会启动部分采集。多个具体 ID 若归属于同一模型家族，只执行一次实际采集，并在响应中保留具体 ID 到 owner 槽的映射。

手动采集逐个检查配置范围内的「账号 + 模型家族」槽：state **缺失**、按本地一小时保留上限**已实际过期**或最近一次采集**已失败**的槽启动新采集；仍有效的槽记入 `already_valid_models` 而不重复消耗额度。自动周期已到、`due=true` 或自动开关关闭，都不会把一个未报错且仍有效的 state 视为已过期。账号仍必须当前正常可调度。单账号手动入口与管理页一键采集共用该判定，因此失败轮次进入终态后可立即再次提交。

响应不包含完整 state，只返回脱敏诊断。常见结果：

- `202 Accepted` + `status: "queued"`：至少一个 owner 槽已启动异步采集、同路由回放和 CAS 持久化。每个 owner 都独立轮询完整 IP 池，但同账号的 owner 串行执行。
- `200 OK` + `status: "already_valid"`：本轮全部 owner 槽都有未实际过期且最近无错误的已验证状态，未发起新请求。
- `409 Conflict` + `status: "rejected"`：账号不支持 Codex Turn State、当前不可调度、模型范围无可用具体模型、真实目录不可用、范围在排队前发生变化，或任一目标 owner 已有采集/持久化工作。最后一种情况返回 `reason: "collection_already_in_flight"`，本批次不会部分排队，应在现有工作结束后重试。

结果中的 `target_models` 保留配置或目录展开出的具体 ID；`model_targets` 提供每个具体 ID 对应的 owner 槽；`queued_models` 与 `already_valid_models` 使用可直接匹配 `codex_turn_state_auto.models` 的 owner key。`successful_models`、`collection_succeeded`、`status`、`reason`、`message` 和 `codex_turn_state_auto` 都是脱敏诊断。`queued` 后应通过账号列表 / 详情重新读取各 owner 状态，不应将 HTTP 202 视为候选已经完成回放与 CAS 发布。

## 注入优先级与必须携带

注入优先级为：**已确认属于当前账号、当前模型家族的客户端原生续链 state → 当前账号、当前模型家族的已验证自动 state**。自动缓存不覆盖可用的客户端原生值。

自动开关开启时，只有命中模型范围的 Codex 请求才会注入自动 state；同账号、同模型家族下的值还必须已验证且未过期。发送前及 HTTP 重试前都会重新校验范围并选择状态；本地缓存缺失时会同步读取该账号的持久化槽。数据库查找失败会返回固定错误，不会借用其他账号或其他模型的状态。

HTTP 头只在 WebSocket 握手时发送，不能改写已有连接的握手。池化连接按模型家族和实际 state 区分；模型家族切换、state 到期或从无状态变为有状态时不能沿用旧握手。Passthrough 在后续 `response.create` 转发前校验；需要换状态或模型时以 1013 提示客户端重连，在途响应不自动重放。

## 系统设置 API

```json
{
  "openai_codex_turn_state_auto_enabled": true,
  "openai_codex_turn_state_auto_interval_minutes": 50,
  "openai_codex_turn_state_default_model": "gpt-5.5",
  "openai_codex_turn_state_models": "gpt-5.5,gpt-6-astra-*",
  "openai_codex_turn_state_proxy_urls": [
    "socks5://username:password@host:port"
  ]
}
```

使用 `PUT /api/v1/admin/settings`。字段省略或 `null` 表示保留原值；关闭自动开关不删除已采集的账号状态。

- `openai_codex_turn_state_auto_enabled`：是否自动触发、注入和续期；不影响管理员手动采集。
- `openai_codex_turn_state_auto_interval_minutes`：有效状态进入下一次自动采集的周期，整数 1 到 60，默认 50。周期从最近一次成功采集或复验起算，到期后由命中该账号与模型的活跃业务请求提前触发续采；状态实际过期时间始终是硬边界，已有模型槽到达该边界后由每分钟扫描一次的后台任务自动续期。该设置不改变五分钟失败退避、持久化 `Retry-After` 或「后台不首次采集空槽」边界。
- `openai_codex_turn_state_default_model`：自动链路无法从请求上下文取得模型时使用的单个模型 ID，最多 128 字节，允许字母、数字及 `-_.:/`；空值恢复内置值。手动全范围采集不使用它缩小目标集。
- `openai_codex_turn_state_models`：模型范围，逗号或换行分隔、忽略大小写并去重，规范化后最多 1024 字节。空值表示全部模型；支持精确值和仅在末尾的 `*` 前缀通配，其他位置的通配符会拒绝保存。
- `openai_codex_turn_state_proxy_urls`：Turn State 专用 IP 池，只接受带非空用户名、密码、host 和 `1..65535` 端口的 SOCKS5 URL，单项最多 2048 字节，整池最多 256 项，规范化后稳定去重。空数组或字段未配置时回退全局 IP 管理池；非空专用池不会回退全局池或账号绑定代理。

模型范围同时约束自动采集、自动注入和管理员手动采集。专用代理凭据作为管理员设置保存并回显给独立页面；应按敏感配置保护管理端权限和数据库访问。应用日志、采集错误和账号诊断不会输出代理 URL、用户名或密码。
运行中缩小模型范围时，已验证状态会保留但不再向范围外模型注入；尚未发布的探测和候选值会取消，后续重新放开范围时可继续使用未过期的已验证状态。

调试工作台不再提供 Turn State 四阶段验收、状态回放或回合续接控件。每次普通调试请求都以新的独立 session 执行；实际链路记录中经脱敏的响应头仍可作为通用调试证据查看。

## 账号诊断与日志

账号详情和列表的 `codex_turn_state_auto` 为只读脱敏诊断，包含 `configured`、`collection_succeeded`、`successful_models`、`set_at_ms`、`probe_at_ms`、`verified_at_ms`、`verified_model`、`probe_not_before_ms`、`expires_at_ms`、`due`、`last_error`、`recovery_pending`、`invalidated_at_ms` 以及按模型分组的 `models`，不包含完整 state。`successful_models` 稳定去重展示已成功验证的实际模型；`due` 可以包含提前续期窗口，不等于「已实际过期」。

`last_error` 只返回固定错误码，不包含上游错误正文、代理地址或凭据。Turn State 受管 `account.extra` 字段从普通账号 DTO、导出、导入和复制中移除；普通账号编辑也不会覆盖它们。

管理员使用日志的「上游 Turn State」列默认只显示实际字符长度；长度仅供诊断。`upstream_turn_state` 保存实际出站时的快照，`upstream_response_model` 保存真实上游模型原文。列表与应用 stdout 不新增完整 state 或代理凭据。

## 覆盖路径与边界

自动注入覆盖 Responses HTTP（JSON / SSE）、Responses 透传、`/responses/compact`、经共同 Responses 链路转发的 Chat Completions / Messages 兼容请求、HTTP → WebSocket 桥接，以及 WebSocket 入站、池化 / 专用连接和 passthrough 直连握手。

维护请求仍有每路由有限网络超时、完整去重路由快照、每路由前续期的一分钟持久化短租约、响应体上限、429 持久化边界、凭据错误、可打印 ASCII 校验、账号可调度性、模型范围、账号 / 模型归属和候选回放边界。短租约续期不增加本轮 attempt，实例崩溃后也不会按 IP 池大小长时间占用槽位；业务请求触发的自动路径保留专用用量证据，后台续期 / 失败重采与手动路径在同路由回放后直接进入独立持久化，三者最终都受 CAS 发布约束。

模拟上游或历史真实账号联调只能证明当次流程与证据链表现，不代表上游一定签发新 state，也不构成模型质量改善或规避 Overload 的保证。
